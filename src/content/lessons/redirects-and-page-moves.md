Представьте, что урок был доступен по адресу `/lessons/site-map/`, а теперь находится на `/lessons/sitemap-xml/`. Старая ссылка может остаться в закладках и чужих статьях. Настройте сервер так, чтобы переход по ней открывал тот же урок на новом адресе.

## Выберите ответ старого адреса

| Что произошло | Как отвечает сервер |
| --- | --- |
| Урок навсегда переехал | `301` с заголовком `Location`, который указывает на новый адрес |
| Подмена адреса временная | `302`, пока посетителей нужно направлять на временный URL |
| Страницу удалили, подходящей замены нет | `404` или `410` |

Страница ошибки может предложить программу курса или поиск по сайту. Проверьте её HTTP-статус. Если шаблон пишет «Страница не найдена» и при этом сервер отвечает `200`, Google может определить ответ как `soft 404`. Массовый перенаправляющий ответ на главную тоже создаёт проблему, когда она не помогает найти содержимое удалённой страницы.

## Перенесите страницу и обновите ссылки

Сначала опубликуйте новый адрес и проверьте, что он отдаёт `200`. Затем настройте прямой редирект со старого адреса на конечный, чтобы посетитель не проходил через цепочку промежуточных URL. В статическом проекте правило обычно добавляют на хостинге или в веб-сервере. Например, внутри блока `server` в Nginx:

```nginx
location = /lessons/site-map/ {
    return 301 /lessons/sitemap-xml/;
}
```

Для теста используйте изолированную копию сайта. В примере правило совпадает только с указанным путём. Если сайт раньше раздавал и вариант без завершающего слеша, проверьте оба адреса.

Обновите внутренние ссылки и оставьте в [sitemap](/lessons/sitemap-xml/) новый URL. Проверьте [canonical](/lessons/canonical-urls/) на новой странице. Старый адрес должен оставаться доступен для запроса, чтобы и посетитель, и робот могли получить редирект.

## Проверьте перенос

Подставьте тестовый или опубликованный домен вместо `seo.example.com`:

```sh
curl -sS -D - -o /dev/null https://seo.example.com/lessons/site-map/
curl -sS -L -o /dev/null -w '%{http_code} %{url_effective} %{num_redirects}\n' https://seo.example.com/lessons/site-map/
curl -sS -D - -o /dev/null https://seo.example.com/lessons/removed-example/
```

Первый запрос должен показать `301` и новый адрес в `Location`. Второй должен завершиться с `200` на новом URL. Для этого примера ожидается один переход. Последний запрос проверьте по заранее выбранному отсутствующему адресу: сервер должен вернуть `404` или `410`, в зависимости от настройки.

## Если переезжает весь сайт

Составьте список соответствий старых и новых URL. Проверьте самые посещаемые страницы и выборку из каждого раздела. При смене домена используйте соответствующую процедуру Google Search Console и Яндекс Вебмастера, затем наблюдайте индексирование и трафик на обоих адресах. Для переименования одного пути достаточно настроить и проверить сам перенос.

## Практика

1. Настройте перенос одного тестового URL на существующую страницу и запишите пару адресов.
2. Проверьте редирект командами выше. Затем запросите заведомо отсутствующий URL, чтобы увидеть реальный HTTP-статус страницы ошибки.
3. Проверьте ссылки, canonical и sitemap. Для опубликованного переноса позже сравните статус старого и нового адресов в панелях вебмастеров.
