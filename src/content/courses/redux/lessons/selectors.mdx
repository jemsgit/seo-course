# Селекторы и производные данные

<div className="learning-note"><strong>После урока ты сможешь</strong><p>Выносить вычисления в селекторы и хранить минимальное исходное состояние.</p></div>

Перед началом: пройди [предыдущий урок](/redux/lessons/immer/).

## Не храни то, что легко вычислить

Допустим, у нас есть задачи и фильтр. Если хранить ещё и `visibleTasks`, при каждом изменении придётся синхронно обновлять два списка. Пропущенное обновление создаст противоречие.

Храни исходные задачи и выбранный фильтр. Видимый список вычисляй при чтении. Такая функция называется селектором.

```ts
type Task = { id: string; title: string; done: boolean };
type State = { tasks: Task[]; filter: 'all' | 'active' };
export const selectTasks = (state: State) => state.tasks;
export const selectActiveCount = (state: State) =>
  state.tasks.filter(task => !task.done).length;
export const selectVisibleTasks = (state: State) =>
  state.filter === 'all' ? state.tasks : state.tasks.filter(task => !task.done);
```

В этом примере `state.tasks` — массив всех задач, а `state.filter` — выбранный фильтр. `selectTasks` возвращает исходный массив, `selectActiveCount` считает невыполненные задачи, а `selectVisibleTasks` выбирает задачи для отображения.

Например, в store две задачи: выполненная и невыполненная. При фильтре `'active'` селектор вернёт только невыполненную. **В store по-прежнему останутся обе задачи.** Способ хранения здесь не меняется: мы вычисляем видимый список из исходных данных.

В лаборатории ниже используется такая же структура: массив `tasks` и поле `filter`. Сравни исходное состояние store с результатом селектора — они показаны отдельно.

## Селектор — граница между данными и UI

Компонент вызывает `useAppSelector(selectActiveCount)`. Он знает, что получает число активных задач, и не обязан знать все детали дерева. Если структура state изменится, основную логику чтения можно поправить в одном месте.

Не добавляй в селектор текущую дату, случайное число или сетевой запрос без явной причины: одинаковый вход должен давать предсказуемый результат. Если для вычисления нужна дата, передай её как входной аргумент или храни подходящее событие во времени.

## Цена нового массива

`filter()` каждый раз возвращает новый массив. Для простого числового счётчика это не проблема сравнения ссылок: `useSelector` видит число. Для массива новая ссылка может вызвать ненужное обновление компонента при несвязанных действиях. В следующем уроке решим это через `createSelector`.

Не нужно заранее мемоизировать каждый доступ к полю: `state => state.filter` уже дешёвый и возвращает стабильный примитив.

**Эксперимент:** переключай фильтр и посмотри на список и состояние. Количество сохранённых задач не уменьшается. Удаления не произошло: мы только выбрали часть данных для UI.

## Что запомнить

Селекторы читают и вычисляют. Store хранит исходные данные, а не все возможные их представления. Мемоизация полезна там, где есть преобразование или важна стабильная ссылка.
