# Сквозной проект: список задач

<div className="learning-note"><strong>После урока ты сможешь</strong><p>Подключить серверный список к React, сохранить фильтр в URL и проверить, как интерфейс ведёт себя при успешном и неуспешном сохранении.</p></div>

Перед началом повтори [подключение RTK Query](/redux/lessons/rtk-query-setup/) и [инвалидацию через tags](/redux/lessons/tags/).

## Попробуй готовый проект

Выбери «В работе» и посмотри, как в адресе появится `?status=open`. Нажми «Назад» в браузере, чтобы восстановить предыдущий фильтр. Затем переименуй задачу. С включённой имитацией ошибки форма сохранит введённый текст. Сними отметку и нажми «Сохранить» ещё раз. После успешного ответа список обновится.

Учебный API хранит задачи в памяти. После перезагрузки вернутся исходные названия, а фильтр восстановится из адреса.

## Запусти исходники

<a href="/downloads/redux-task-board.tar.gz" download>Скачать заготовку, готовый проект и тест</a>.

Распакуй архив, открой папку `redux-task-board` и выполни команды. Понадобится Node.js 22.23.4 или новее.

```sh
npm install
npm run dev:starter
```

`/starter.html` открывает заготовку из `starter.tsx`. Главная страница показывает готовый вариант. Можно проходить шаги в заготовке и сверяться с файлами решения.

## 1. Подключи список

В `starter.tsx` создай один учебный транспорт через `createDemoApi()` и передай `demo.fetch` в `createTaskBoard()` из `tasks-api.ts`. Посмотри, как в этом файле устроены `createApi` и `configureStore`. У API есть собственный reducer и middleware.

Передай `store` в `<Provider>`, а `api` передай компоненту списка. Внутри компонента вызови хук:

```tsx
const { data: tasks, isFetching, isError, refetch } = api.useGetTasksQuery();
```

Выведи названия задач. Пока данных нет, покажи загрузку. При повторном чтении оставь уже полученные задачи на экране. Для ошибки списка добавь кнопку с `refetch()`.

## 2. Добавь фильтр в URL

Используй `status=open` для задач в работе и `status=done` для готовых. Без параметра покажи все задачи. При выборе фильтра обновляй URL через `history.pushState`. Подпишись на `popstate`, чтобы кнопки браузера восстанавливали прежний выбор.

Фильтруй массив из `useGetTasksQuery()` при отображении. Один и тот же результат GET подходит для всех трёх вариантов. Проверь, что при смене фильтра нового запроса нет. Пример находится в `TaskBoard.tsx`.

## 3. Добавь переименование

Открывай форму с текущим названием и храни черновик в локальном состоянии строки. При отправке вызови `renameTask({ id, title }).unwrap()`. Пока запрос выполняется, отключи кнопку сохранения. При ошибке покажи сообщение в форме и оставь черновик для повторной отправки.

`getTasks` предоставляет тег `Tasks`. При успешном PATCH `renameTask` инвалидирует этот тег. RTK Query повторяет GET и обновляет список, поэтому форме достаточно закрыться после успешного сохранения. В этом проекте обработанный отказ API сохраняет прежний список. Это можно проверить, включив ошибку в `TaskBoardDemo.tsx`.

## 4. Проверь сценарий целиком

На том же Vite-сервере открой `/test.html`. Файл `browser-test.tsx` монтирует `TaskBoard` с настоящим `Provider` и новым store. На границе HTTP стоит учебный транспорт, который регистрирует методы запросов.

Тест открывает готовые задачи по URL, переключает фильтр и проверяет навигацию назад. Затем он сохраняет название с ошибкой и проверяет, что черновик остался. После повторного сохранения тест ждёт нового названия в списке. Ожидаемый журнал запросов выглядит так:

```text
GET → PATCH (ошибка) → PATCH (успех) → GET
```

Если цепочка отличается, сравни журнал теста с действиями в Redux DevTools. Например, успешный PATCH без последующего GET при открытом списке — повод проверить, совпадают ли теги у двух endpoints.
