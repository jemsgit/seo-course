# selectFromResult: выбираем нужную часть ответа

<div className="learning-note"><strong>После урока ты сможешь</strong><p>Выбрать часть query-результата и объяснить, какие изменения заставят компонент обновиться.</p></div>

Перед началом: пригодятся [мемоизация](/redux/lessons/memoization/) и [основы queries](/redux/lessons/queries/).

## Когда весь ответ не нужен

Список загрузил сто записей, а маленькая карточка показывает только одну. Если карточка читает весь результат, изменение другой записи может затронуть её подписку. `selectFromResult` позволяет вернуть только значения, необходимые конкретному компоненту.

Это настройка hook, а не новый endpoint и не дополнительный запрос. Кэш по-прежнему содержит полный ответ.

```tsx
// api.getPosts возвращает Post[], где Post = { id: number; title: string }.
function PostCard({ id }: { id: number }) {
  const { post } = api.useGetPostsQuery(undefined, {
    selectFromResult: ({ data }) => ({
      post: data?.find(item => item.id === id),
    }),
  });
  return <p>{post?.title ?? 'Запись пока недоступна'}</p>;
}
```

Пример предполагает endpoint `getPosts` без аргумента и импорт `api` из твоего API-модуля. `undefined` — его аргумент, второй объект — настройки hook.

## Что именно сравнивается

RTK Query использует поверхностное сравнение возвращённого объекта. Создать сам объект `{ post }` нормально: важно, сохранились ли значения его полей. Когда другая запись меняется, ссылка выбранной записи может остаться прежней благодаря структурному разделению данных.

Если вернуть `isFetching`, изменения этого флага тоже станут причиной обновления. Возвращай все нужные UI значения, но не добавляй их автоматически «на всякий случай».

```tsx
selectFromResult: ({ data, isFetching }) => ({
  post: data?.find(item => item.id === id),
  isFetching,
})
```

## Новая ссылка может испортить эффект

`filter()` или `map()` внутри callback создают массив. При каждом выполнении такая новая ссылка может свести пользу сравнения к минимуму. Для преобразований используй подходящий мемоизированный селектор из урока 8.

Для пустого результата вынеси массив за пределы компонента:

```tsx
const emptyPosts: Post[] = [];
// В настройках hook:
selectFromResult: ({ data }) => ({ posts: data ?? emptyPosts })
```

Здесь `Post` — тип записи API. Вариант `data ?? []` создавал бы новый пустой массив при каждом выполнении callback до загрузки данных.

## Эксперимент

Дождись начальных данных и измени только запись 2. Полная карточка должна обновиться, а карточка записи 1 — сохранить прежний результат подписки. Затем измени запись 1: её выбранное значение изменилось, поэтому обновление ожидаемо.

Счётчики показывают вызовы рендера в этом изолированном примере. В обычном приложении компонент также может обновляться из-за props, context и родителя. Режим разработки React может давать дополнительные вызовы. Не воспринимай `selectFromResult` как запрет любого рендера.

## Что запомнить

Оптимизация касается выбранного результата подписки. Она не уменьшает ответ сервера и не создаёт отдельный кэш для каждого компонента. Начинай с понятного UI, затем выбирай данные точнее там, где это полезно.
