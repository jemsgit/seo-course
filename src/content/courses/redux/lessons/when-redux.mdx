# Когда нужен Redux

<div className="learning-note"><strong>После урока ты сможешь</strong><p>Отличать виды состояния и выбирать для каждого подходящий инструмент.</p></div>

Перед началом: пригодится знакомство с JavaScript, React и асинхронными функциями.

## Сначала проблема, потом библиотека

Представь список задач: есть поле ввода, фильтр и список с сервера. Это три разных вида данных. Значение поля нужно только форме. Фильтр может понадобиться списку и панели статистики. Задачи приходят извне и должны оставаться согласованными с сервером.

Redux полезен, когда общее состояние меняется по сложным правилам, используется в разных частях приложения и важно понимать историю изменений. Он добавляет понятия и код, поэтому подключать его к каждому переключателю необязательно.

## Где хранить данные

| Данные | Первое разумное место | Почему |
| --- | --- | --- |
| Незавершённый текст формы | `useState` компонента | Остальным частям приложения он пока не нужен |
| Фильтр, который должен сохраняться в ссылке | URL | Ссылку можно передать и открыть заново |
| Общий режим интерфейса | Redux slice, если Redux уже используется | Несколько компонентов читают единое значение |
| Список задач с сервера | RTK Query | Нужны загрузка, кэш и обновление после изменений |

Context может передавать значение по дереву React. Выбор между ним и Redux зависит от объёма логики, частоты обновлений, требований к отладке и существующей архитектуры. Само наличие нескольких потребителей ещё не требует Redux.

```tsx
function TaskInput() {
  const [text, setText] = useState('');
  // В Redux попадёт готовое событие добавления задачи,
  // а не обязательно каждое нажатие клавиши.
  return <input value={text} onChange={e => setText(e.target.value)} />;
}
```

Здесь `useState` импортируется из React. Это фрагмент формы, а не полный проект. Когда пользователь подтвердит ввод, можно отправить `taskAdded({ title: text })` или вызвать mutation RTK Query.

## Не создавай две правды

Если RTK Query уже хранит ответ сервера, не копируй весь ответ в обычный slice «на всякий случай». Придётся вручную решать, какая копия актуальна. В slice обычно достаточно хранить клиентские настройки, например выбранный id. Для редактируемого черновика отдельная копия допустима: у неё другая задача и явные правила сохранения.

**Эксперимент:** возьми экран своего проекта и выпиши пять значений. Для каждого ответь: кто его читает, откуда оно пришло, нужно ли хранить его в URL, кто отвечает за обновление? Только затем выбирай хранилище.

## Что запомнить

Redux — инструмент организации общего состояния. RTK Query решает отдельную задачу серверных данных. Локальное состояние React продолжает использоваться вместе с ними.
