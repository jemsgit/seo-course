# Как Redux обновляет интерфейс

<div className="lead">Нажатие кнопки, одно действие, новое состояние. Посмотрим, что происходит между ними — и почему интерфейс знает, когда обновиться.</div>

<div className="learning-note"><strong>После урока ты сможешь</strong><p>Проследить путь действия до интерфейса и предсказать, каким станет состояние после нескольких действий.</p></div>

Понадобится базовое знакомство с функциями и объектами JavaScript и компонентами React. TypeScript в примерах помогает описывать данные; сложные типы здесь не нужны. Устанавливать что-либо для стенда не требуется.

Redux хранит общее состояние приложения и задаёт правила его изменения. Для отдельного счётчика достаточно локального состояния React. Здесь счётчик нужен как маленький пример, в котором виден весь механизм.

<h2 id="terms">Пять понятий — один поток</h2>

Представь два компонента, которым нужно одно и то же число. Они читают его из общего хранилища. Когда пользователь нажимает «+1», компонент сообщает о событии, а правила обновления вычисляют следующее состояние.

| Понятие | Что означает в нашем примере |
| --- | --- |
| **State — состояние** | Объект с текущими данными: `{ counter: { value: 0 } }` |
| **Store — хранилище** | Объект Redux, который хранит состояние, принимает действия и уведомляет подписчиков |
| **Action — действие** | Обычный объект с типом события: `{ type: 'counter/increment' }` |
| **Dispatch — отправка действия** | Вызов `store.dispatch(action)`, который передаёт действие в хранилище |
| **Reducer — редьюсер** | Функция, вычисляющая следующее состояние по предыдущему состоянию и действию |

<div className="flow" aria-label="Поток данных">Событие в UI <span>→</span> dispatch(action) <span>→</span> reducer <span>→</span> новое состояние <span>→</span> UI</div>

Action описывает событие. Сам объект ничего не меняет. Reducer определяет, как реагировать на это событие. В reducer нет места запросам к серверу, таймерам и другим побочным эффектам.

<h2 id="code">Теперь свяжем происходящее с кодом</h2>

### 1. Описываем состояние и правила

`createSlice` объединяет начальное состояние и обработчики действий. Он создаёт reducer и функции, которые возвращают объекты действий. Эти функции называются action creators.

```ts
import { configureStore, createSlice } from '@reduxjs/toolkit';

const counterSlice = createSlice({
  name: 'counter',
  initialState: { value: 0 },
  reducers: {
    increment(state) { state.value += 1; },
    decrement(state) { state.value -= 1; },
  },
});

export const { increment, decrement } = counterSlice.actions;

export const store = configureStore({
  reducer: { counter: counterSlice.reducer },
});

export type RootState = ReturnType<typeof store.getState>;
export type AppDispatch = typeof store.dispatch;
```

Имя `counter` и имя обработчика `increment` образуют тип действия `counter/increment`. Вызов `increment()` создаёт action; `store.dispatch(increment())` отправляет его в store.

Запись `state.value += 1` выглядит как изменение прежнего объекта. В обработчиках `createSlice` Redux Toolkit использует Immer: мы работаем с черновиком, а библиотека создаёт неизменяемое обновление. Это не разрешение менять состояние, полученное через `store.getState()`, напрямую.

### 2. Подключаем React

`Provider` делает store доступным компонентам внутри него. `useSelector` выбирает нужное значение, а `useDispatch` позволяет отправить действие.

```tsx
import { Provider, useDispatch, useSelector } from 'react-redux';
import { store, increment, type RootState, type AppDispatch } from './store';

function Counter() {
  const value = useSelector((state: RootState) => state.counter.value);
  const dispatch = useDispatch<AppDispatch>();

  return (
    <button onClick={() => dispatch(increment())}>
      Значение: {value}. Добавить один
    </button>
  );
}

export function App() {
  return <Provider store={store}><Counter /></Provider>;
}
```

Селектор здесь возвращает число. После действия React Redux сравнивает выбранное значение с предыдущим. Если оно изменилось, компоненту требуется обновление. Изменение любой части store не означает, что каждый компонент обязательно перерисуется.

### 3. Проверяем порядок

Для обычного действия reducer выполняется синхронно. Сразу после возврата из `dispatch` можно прочитать новое состояние:

```ts
store.dispatch(increment());
console.log(store.getState().counter.value); // 1, если до этого было 0
```

Обновление DOM выполняет React. Синхронное обновление store и отображение результата браузером — разные этапы. Именно поэтому кнопки «Далее» в стенде разбирают запись операции, а не замедляют работающий reducer.

<h2 id="takeaway">Что запомнить</h2>

- Компонент сообщает о событии через `dispatch(action)`.
- Reducer вычисляет следующее состояние; store сохраняет результат и уведомляет подписчиков.
- React Redux связывает компоненты с хранилищем через `Provider` и хуки.
- Следующее действие работает с результатом предыдущего.

**Проверь понимание:** если действие создано вызовом `increment()`, но не передано в `dispatch`, изменится ли число? Нет: мы только создали обычный объект.

Для самостоятельного эксперимента отправь «−1» при нуле. Получится −1: ограничения задаёт reducer, и в нашем примере запрета на отрицательные числа нет.
