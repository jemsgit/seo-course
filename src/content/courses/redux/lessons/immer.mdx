# Иммутабельность и Immer

<div className="learning-note"><strong>После урока ты сможешь</strong><p>Различать изменение черновика и прямую мутацию состояния.</p></div>

Перед началом: пройди [предыдущий урок](/redux/lessons/payload-and-events/).

## Старое состояние должно оставаться старым

Иммутабельное обновление создаёт новые ссылки для изменившихся данных и сохраняет прежние значения. Это позволяет сравнивать результаты, воспроизводить действия и использовать историю в DevTools.

## Что такое Immer

**Immer — отдельная JavaScript-библиотека, которая помогает писать иммутабельные обновления привычными присваиваниями.** Redux Toolkit уже использует её внутри `createSlice` и `createReducer`: для этих API отдельно подключать Immer не требуется.

Это не другой синтаксис JavaScript. Запись `state.value += 1` остаётся обычным присваиванием. Разница в том, **какой объект мы меняем**: исходное состояние или специальный черновик, который предоставил Immer.

## Одно обновление без Immer и с ним

Пусть в состоянии есть задача и настройки интерфейса. Хотим отметить задачу выполненной, сохранив прежнее состояние:

```ts
const previousState = {
  task: { title: 'Понять Immer', done: false },
  settings: { theme: 'light' },
};
```

Без Immer создадим новый корневой объект и новый объект изменившейся задачи. Оператор `...` копирует поля только одного уровня, поэтому вложенную задачу копируем отдельно:

```ts
const nextState = {
  ...previousState,
  task: {
    ...previousState.task,
    done: true,
  },
};
```

С Immer такое же обновление можно описать через `produce`. Это самостоятельный пример использования библиотеки; внутри `createSlice` вызывать `produce` вручную не нужно:

```ts
import { produce } from 'immer';

const nextState = produce(previousState, draft => {
  draft.task.done = true;
});
```

Это два альтернативных варианта, а не один файл с двумя объявлениями `nextState`. В обоих случаях результат такой:

```ts
previousState.task.done;                  // false — прежние данные сохранены
nextState.task.done;                      // true
nextState === previousState;             // false — новый корневой объект
nextState.task === previousState.task;   // false — задача изменилась
nextState.settings === previousState.settings; // true — настройки не менялись
```

Immer не копирует всё дерево без необходимости: неизменившиеся части могут сохранить ссылки.

## Что такое черновик и почему это безопасно

Черновик, или `draft`, — специальное представление состояния, через которое Immer отслеживает изменения объектов и массивов. Это не готовая глубокая копия всего state. Ты описываешь правки черновика, а Immer формирует результат, сохраняя исходные данные.

Порядок работы:

1. Immer получает прежнее состояние.
2. Вызывает обработчик и даёт ему черновик.
3. Отслеживает присваивания и операции вроде `push`.
4. Возвращает следующее состояние с нужными новыми ссылками.

Если изменений нет, Immer может вернуть прежнее состояние. Черновик предназначен для работы внутри обработчика: не сохраняй его в переменную снаружи и не используй позже.

## Как это выглядит внутри createSlice

В обработчике `createSlice` параметр обычно называют `state`, но для объекта или массива это **черновик состояния конкретного слайса**. Название переменной не делает его исходным состоянием: при желании его можно назвать `draft`.

Поэтому вместо ручного копирования каждого изменяемого уровня можно написать:

```ts
// Фрагмент reducers или extraReducers для слайса с полем task:
completed(state) {
  state.task.done = true;
}
```

Redux Toolkit выполняет этот обработчик через Immer. В store попадёт иммутабельно обновлённый результат; прежнее состояние не изменится. Это работает и в `reducers`, и в `extraReducers`.

Другой пример — переключение задачи в слайсе, состояние которого представляет собой массив:

```ts
// Обработчик внутри createSlice с массивом Task[]:
toggled(state, action: PayloadAction<string>) {
  const task = state.find(task => task.id === action.payload);
  if (task) task.done = !task.done;
}
```

`PayloadAction` импортируется из `@reduxjs/toolkit`. Когда обработчик завершится, Immer получит следующее состояние. Изменившаяся задача и содержащий её массив получат новые ссылки; нетронутые элементы могут сохранить прежние.

## Два допустимых способа

Можно изменить черновик **или** вернуть замену. Не делай оба действия в одном обработчике.

```ts
// Допустимо: изменение черновика.
added(state, action) { state.push(action.payload); }

// Допустимо: замена массива.
cleared() { return []; }

// Ошибка: push возвращает число, а стрелка неявно его возвращает.
// added: (state, action) => state.push(action.payload)
```

У обработчика `added` используй тип `PayloadAction<Task>`, как в уроке 3. Примеры выше подчёркивают форму тела функции.

## За пределами reducer черновика нет

```ts
const tasks = store.getState().tasks;
// tasks.push(newTask); // Не изменяй данные store напрямую.
store.dispatch(added(newTask));
```

Здесь предполагается store с массивом задач и `newTask` типа `Task`. Селекторы также не получают разрешения на мутации. `sort()` меняет массив на месте: используй копию `tasks.slice().sort(...)`, если сортировка нужна для отображения.

Важный случай: извлечённое примитивное значение не является черновиком. `let done = task.done; done = !done` не обновит `task.done`. Меняй поле самого объекта-черновика.

**Эксперимент:** переключи задачу в стенде. Redux Toolkit создаёт новое состояние; данные не меняются напрямую из компонента. В тестах проекта дополнительно проверяем, что сохранённая ссылка на прежнее состояние сохраняет прежние значения.

## Что запомнить

Immer разрешает удобный синтаксис внутри поддерживаемых обработчиков. Он не отменяет иммутабельность и не превращает любые данные приложения в изменяемый state.
