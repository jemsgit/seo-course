Представьте, что у курса появился английский перевод урока о карте сайта. Русский урок по-прежнему доступен по старому адресу. Английский получает свой URL и ссылку из переключателя языка. Через `hreflang` мы можем подсказать поисковикам, что эти две страницы отвечают на один вопрос на разных языках.

## Дайте каждой версии свой адрес

В примере русский урок остаётся на `/seo/lessons/sitemap-xml/`, а английский открывается по `/en/lessons/sitemap-xml/`. Оба адреса должны быть доступны напрямую. Пользователь, который выбрал English, попадает на перевод текущего урока.

Язык и регион обозначают разные вещи. `en` подходит для английского без привязки к стране. `en-GB` уместен, если есть версия для Великобритании с отличающимися условиями или примерами. Код страны сам по себе язык не задаёт. Для сайта, который только переводит уроки, достаточно кодов `ru` и `en`.

Оставьте обычные ссылки для переключения языка. Если сразу перенаправлять всех по IP или языку браузера, пользователь может потерять доступ к нужной версии, а поисковик может её не обойти. Предложите переключиться и дайте открыть оба адреса напрямую.

## Добавьте ссылки на переводы в HTML

Вставьте один и тот же набор ссылок в `<head>` русского и английского уроков. В набор входит ссылка на саму страницу и ссылка на её перевод:

```html
<link rel="alternate" hreflang="ru"
      href="https://seo.example.com/seo/lessons/sitemap-xml/">
<link rel="alternate" hreflang="en"
      href="https://seo.example.com/en/lessons/sitemap-xml/">
```

Здесь `seo.example.com` и английский адрес используются для упражнения. Для публикации укажите абсолютные URL доступных переводов. Если английская страница уже ссылается на русский урок, а русский урок пока не ссылается обратно, Google может проигнорировать такую пару. В статической сборке удобно создавать обе группы ссылок из одной записи о переводах.

Если есть отдельная страница выбора языка, можно указать её как `hreflang="x-default"` для пользователей, которым не подходит ни одна из указанных версий. Для пары переводов без такой страницы достаточно двух ссылок из примера.

Google поддерживает передачу языковых связей через HTML, HTTP-заголовки или XML-карту. Яндекс документирует разметку в `<head>` и больше не поддерживает передачу языковых связей через sitemap. Для HTML-страниц, которые должны обрабатываться обеими системами, используйте `<link>` в исходном HTML. В обычной [карте сайта](/seo/lessons/sitemap-xml/) перечислите опубликованные адреса каждой языковой версии.

## Согласуйте hreflang с canonical

В этом примере обе страницы самостоятельны: у каждой свой перевод и свой канонический URL. Русский урок указывает `canonical` на русский адрес, английский на английский. Если английский урок объявить дублем русского, `canonical` и `hreflang` будут сообщать поисковику разные предпочтения. Сначала проверьте, [какой адрес поисковик считает основным](/seo/lessons/canonical-urls/).

Если перевода ещё нет, оставьте в разметке только доступные версии. Когда перевод выйдет, обновите переключатель и HTML обеих страниц в одной сборке.

## Практика

1. Возьмите два перевода одной страницы или создайте их в тестовой копии сайта. Назначьте два URL. Убедитесь, что каждый отдаёт `200` и показывает нужный язык без принудительного перенаправления.
2. Добавьте один набор `hreflang` в оба HTML-файла. Запросите каждый адрес через `curl` и сравните ссылки в `<head>`. Проверьте обратную ссылку, адрес самой страницы и её `canonical`.
3. Откройте русский URL и переключитесь на английский. Затем вернитесь обратно. После публикации проверьте доступность и индексирование обоих адресов в панелях вебмастеров. Отдельно посмотрите, какая версия появляется по запросу на каждом языке.
