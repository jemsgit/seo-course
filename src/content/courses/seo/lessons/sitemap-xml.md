Если робот уже знает о главной странице блога, он может перейти оттуда в рубрику и открыть ссылки на статьи. Такой блог может индексироваться и появляться в выдаче без `sitemap.xml`. В каталоге с тысячами карточек сложнее проверить, ведут ли ссылки ко всем нужным страницам. Карта даёт роботу дополнительный список URL для обнаружения.

## Когда стоит сделать карту сайта

Для небольшого блога сначала проверьте [внутренние ссылки](/seo/lessons/internal-links/). Читатель должен находить статью через рубрику или соседний материал. Для нового сайта с малым числом внешних ссылок или для большого каталога стоит добавить sitemap. В каталоге, например, туда можно включить основные адреса опубликованных карточек, которые находятся глубоко в навигации.

Список адресов помогает обнаруживать страницы. Решение об обходе и включении страницы в индекс поисковик принимает отдельно. Если важной статьи нет в выдаче, проверьте её [по шагам диагностики](/seo/lessons/page-missing-from-search/), даже если адрес есть в карте.

## Что включить в файл

Для каждой страницы, которую хотите видеть в поиске, укажите её собственный канонический URL целиком. Например, для урока это `https://seo.example.com/seo/lessons/sitemap-xml/`. Внутренняя ссылка может выглядеть как `/seo/lessons/sitemap-xml/`, если она ведёт на тот же адрес. У главной и у других уроков свои записи. Страницы с `noindex`, редиректы, ошибки и черновики из карты исключайте.

На сайте этого курса Astro собирает карту из опубликованных уроков. Из того же списка строятся страницы модулей и навигация. Вот сокращённый пример с вымышленным доменом:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url><loc>https://seo.example.com/</loc></url>
  <url><loc>https://seo.example.com/seo/lessons/sitemap-xml/</loc></url>
</urlset>
```

Для большого сайта можно собрать отдельные карты товаров и статей и перечислить их в индексе sitemap. Так проще проверять обработку каждой группы адресов. Если добавляете `lastmod`, указывайте дату последнего существенного изменения страницы. Дата очередной сборки подходит только для реально обновлённых страниц.

## Как поисковик узнаёт о файле

Укажите абсолютный адрес карты строкой `Sitemap: https://seo.example.com/sitemap.xml` в [`robots.txt`](/seo/lessons/robots-txt/). Сборка курса подставляет этот адрес автоматически из `SITE_URL`. Можно также отправить карту в Google Search Console и Яндекс Вебмастере. Там можно проверить, удалось ли её прочитать и есть ли ошибки. Если `robots.txt` отсутствует, карту можно передать через панели.

## Практика

Соберите курс с тестовым доменом из примера:

```sh
SITE_URL=https://seo.example.com npm run build
SITE_URL=https://seo.example.com npm run check
```

1. Откройте `dist/sitemap.xml` и найдите URL этого урока. Сверьте его с `canonical` в `dist/seo/lessons/sitemap-xml/index.html`.
2. Откройте `dist/robots.txt` и проверьте адрес после `Sitemap:`. Найдите на главной ссылку на технический модуль, а в списке модуля — ссылку на этот урок.
3. На своём опубликованном сайте проверьте ответ по адресу карты, отправьте её в панели и запишите статус обработки. Если нужно проверить индексирование урока, откройте отчёт о самом URL.
