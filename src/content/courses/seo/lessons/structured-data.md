## Что такое структурированные данные

Структурированные данные — это сведения о странице, записанные так, чтобы программа могла понять, что означает каждое поле. Например, в карточке товара «3 500 ₽» может быть текущей ценой, старой ценой или стоимостью доставки. В разметке товара можно явно указать, что это цена предложения и что она задана в рублях.

Schema.org задаёт словарь типов и свойств. Например, `Product` обозначает товар, а `BreadcrumbList` — цепочку хлебных крошек. JSON-LD — один из форматов, в котором этот словарь можно использовать. В уроке мы добавляем в HTML блок JSON-LD с названиями и адресами разделов курса.

## Как поисковик использует разметку

Когда поисковик обрабатывает HTML, он может прочитать тип объекта и его свойства. Например, у `BreadcrumbList` он прочитает порядок пунктов и увидит, что урок относится к модулю «Техническое SEO». Если поисковик поддерживает этот тип разметки, он может использовать данные при оформлении результата поиска.

Над заголовком урока уже есть видимые ссылки на главную и модуль. Разметка описывает тот же путь в явном виде, а последний пункт обозначает сам урок. Ссылки нужны читателю для навигации. JSON-LD браузер воспринимает как данные и сам по себе ничего не рисует. Чтобы проверить разметку, откройте исходный HTML или валидатор.

## На каких страницах нужна разметка

Страница может индексироваться и без структурированных данных. Если вы хотите передать поисковику сведения о конкретной странице, добавьте разметку в HTML именно этой страницы. Например, `Product` с ценой и наличием размещают на странице соответствующего товара, а `BreadcrumbList` описывает путь до того урока, который открыт сейчас.

На курсе один шаблон генерирует JSON-LD для каждого урока при сборке с `SITE_URL`. Он подставляет название модуля, заголовок урока и их адреса. Поэтому у двух уроков одного модуля первые пункты совпадают, а последний ведёт на свой урок.

## Как устроена разметка

JSON-LD записывают внутри `<script type="application/ld+json">`. Браузер воспринимает его содержимое как данные. Список `itemListElement` описывает путь от главной до урока. У каждого пункта есть номер `position`, название `name` и адрес `item`. Нумерация начинается с единицы.

Сокращённый пример с тестовым доменом:

```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "BreadcrumbList",
  "itemListElement": [
    {
      "@type": "ListItem",
      "position": 1,
      "name": "SEO Практика",
      "item": "https://seo.example.com/seo/"
    },
    {
      "@type": "ListItem",
      "position": 2,
      "name": "Техническое SEO",
      "item": "https://seo.example.com/seo/modules/technical/"
    },
    {
      "@type": "ListItem",
      "position": 3,
      "name": "Как добавить и проверить структурированные данные",
      "item": "https://seo.example.com/seo/lessons/structured-data/"
    }
  ]
}
</script>
```

Адрес модуля здесь важен, даже если его нет в пути урока. Крошки показывают, где урок находится в программе. Последний пункт использует канонический адрес урока.

## Что проверять после сборки

Откройте исходный HTML и найдите блок JSON-LD. Сверьте порядок и названия с навигацией на странице. Проверьте, что указанные адреса открываются и последний адрес совпадает с `rel="canonical"`. Если в крошках есть ссылка на старый путь с редиректом, обновите её до конечного URL.

Google и Яндекс могут использовать разметку при оформлении результата поиска. Результат валидатора показывает, что инструмент распознал данные и смог их проверить. Отображение в выдаче поисковик выбирает отдельно. У Google хлебные крошки поддерживаются в настольной выдаче, а в мобильной строка адреса показывает домен.

## Практика

1. Соберите курс командой `SITE_URL=https://seo.example.com npm run build`. Откройте `dist/seo/lessons/structured-data/index.html` и проверьте поля всех трёх пунктов. Сборка без `SITE_URL` пропускает JSON-LD, поскольку ей неизвестен домен.
2. Вставьте сгенерированный HTML в режим проверки кода [Google Rich Results Test](https://search.google.com/test/rich-results) и [валидатора Яндекс Вебмастера](https://webmaster.yandex.ru/tools/microtest/). Откройте найденный список и проверьте адреса. Сообщения о тестовом домене или `noindex` разбирайте отдельно от ошибок в структуре списка.
3. На опубликованном сайте проверьте публичный URL. Если в выдаче появилась цепочка, сравните её с разметкой: поисковик может использовать только часть пути или выбрать другие названия.
