Откройте урок в браузере. Если видно заголовок и текст, кажется, что всё готово. Теперь откройте исходный код страницы. Если там только пустой контейнер и ссылка на скрипт, текст появился уже после того, как браузер получил ответ. Для диагностики SEO нужно уметь смотреть на оба состояния страницы.

## Когда появляется HTML

| Подход                       | Кто и когда создаёт HTML                    | Что приходит в первом ответе                                                                                    |
| ---------------------------- | ------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| CSR (Client-Side Rendering)  | Браузер выполняет JavaScript после загрузки | Для полностью клиентской страницы обычно приходят оболочка и скрипты. Текст может появиться после запроса к API |
| SSR (Server-Side Rendering)  | Сервер формирует HTML при запросе           | Готовый текст, если сервер отрендерил его до отправки ответа                                                    |
| SSG (Static Site Generation) | Сборка заранее создаёт HTML-файлы           | Готовый текст из статического файла                                                                             |

SSR и SSG могут вернуть одинаковую разметку. По исходному коду вы проверите, пришёл ли текст сразу. Чтобы отличить SSR от SSG, посмотрите, как приложение собирается и раздаётся. Этот курс использует SSG: `npm run build` создаёт отдельный HTML-файл для каждого опубликованного урока.

## Сравните исходник и DOM

Для упражнения сохраните этот пример как `csr.html` и откройте его в браузере:

```html
<!doctype html>
<html lang="ru">
  <head>
    <meta charset="utf-8" />
    <title>Демо рендеринга</title>
  </head>
  <body>
    <main id="lesson"></main>
    <script>
      const heading = document.createElement("h1");
      heading.textContent = "Как проверить карту сайта";
      document.querySelector("#lesson").append(heading);
    </script>
  </body>
</html>
```

В исходнике строка с названием уже есть внутри скрипта. Сам элемент `<h1>` появится только после выполнения кода. Проверьте его во вкладке **Elements** инструментов разработчика. Если вы просто ищете строку в ответе `curl`, можно принять текст из скрипта за готовый заголовок.

Для сравнения соберите курс командой `npm run build`. Откройте `dist/seo/lessons/sitemap-xml/index.html` и найдите настоящий `<h1>`, абзац из урока и ссылку `<a href>` на соседний материал. Если бы сервер собрал этот же HTML по запросу, это был бы SSR. В обоих случаях браузер получил бы текст и ссылки в первом ответе. JavaScript при этом можно использовать, например, для копирования примера кода.

## Как страницу обрабатывают поисковики

Google может выполнить JavaScript на отдельном этапе рендеринга. Если для текста нужен запрос к API, сбой этого запроса может оставить страницу пустой и после рендеринга. В проверке URL Search Console запустите проверку опубликованной страницы и посмотрите отрендеренный HTML. Наличие текста в этом тесте показывает, что его удалось получить при проверке. Статус в индексе смотрите отдельно.

Яндекс описывает настройки выполнения JavaScript в Вебмастере. Сверьте данные проверки страницы с тем, что отдаёт сервер. Если панель показывает нужный заголовок, но основной текст зависит от JavaScript, проверьте доступность скрипта и API без входа. Особенно полезно проверить страницу в новом приватном окне. В обычной вкладке текст мог загрузиться благодаря сохранённой сессии.

Для публичного урока проверьте в HTML основной текст, ссылки, `title` и [канонический адрес](/seo/lessons/canonical-urls/). Если одно из них появляется лишь после выполнения скрипта, решите, можно ли включить его в ответ сервера или в статическую сборку.

## Что проверить в мобильной версии

Google использует мобильную версию страницы для индексирования. Сравните основной текст, надёжно доступные ссылки и метаданные в мобильном и настольном представлениях. Например, на компьютере карточки видны сразу, а на телефоне их ссылки появляются только после «Показать ещё». Оставьте доступный по обычным ссылкам путь до остальных карточек, например пагинацию, и проверьте отрендеренный HTML в инструменте проверки URL.

[Google о mobile-first indexing](https://developers.google.com/search/docs/crawling-indexing/mobile/mobile-sites-mobile-first-indexing)

## Практика

1. Сравните исходник и DOM файла `csr.html`. Повторите для готового урока из `dist/`.
2. Откройте свой публичный URL через `curl` и в браузере. Найдите заголовок, абзац и обычную ссылку в обоих вариантах. Отметьте, что добавил JavaScript.
3. Если у вас подтверждены права на сайт, проверьте тот же URL в Google Search Console и Яндекс Вебмастере. Запишите отдельно результат проверки доступности, наличие текста в доступном представлении страницы и статус в индексе.
