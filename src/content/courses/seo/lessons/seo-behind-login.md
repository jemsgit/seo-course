В приложении для учёта смен основная работа начинается после входа. Там хранятся расписания и данные сотрудников. Человек из поиска может ещё не знать о продукте: у него задача «как составить график 2/2». Дайте ему открытый пример с вымышленными данными. Если он захочет сохранить график или поделиться им с коллегами, предложите создать аккаунт.

## Что открыть до регистрации

Начните с одной страницы, которая решает часть задачи. Это может быть инструкция, пример или простой калькулятор. Покажите, что приложение делает дальше: например, автоматически пересчитывает смены, когда сотрудник берёт выходной. Посетитель должен понять это без аккаунта. Когда появится другая задача с самостоятельным ответом, под неё можно сделать отдельную страницу.

## Как разместить блог на домене приложения

На одном домене могут жить витрина, публичный блог и кабинет. Например, у сайта `https://example.com` такая структура:

| Путь | Что на нём находится |
| --- | --- |
| `/` | Публичная страница продукта с примером расписания |
| `/blog/` | Публичный список статей |
| `/blog/grafik-2-2/` | Инструкция с примером расчёта графика |
| `/app/` | Кабинет с расписаниями пользователей, доступный после входа |

Блог даёт отдельную страницу для вопроса, который редко уместно подробно раскрывать на витрине. Расскажите в статье, как посчитать смены 2/2, и покажите сам расчёт. После примера можно дать ссылку на продукт для тех, кто хочет составить график для своей команды. Сам путь `/blog/` позиций не добавляет. Он помогает организовать статьи и связать их с витриной.

Добавьте ссылку на блог с главной, а с `/blog/` — обычные ссылки на статьи. Даже если блог и приложение собираются отдельно, хостинг может раздавать их на одном домене по разным путям. Проверьте, что общий маршрут приложения не перенаправляет `/blog/` и вложенные статьи на экран входа.

## Что проверить без аккаунта

- Откройте витрину и несколько статей в приватном окне. Убедитесь, что они возвращают `200`, а основной текст и ссылки доступны в исходном HTML. Проверьте [`canonical`](/seo/lessons/canonical-urls/) каждой статьи и включите публичные адреса в [sitemap](/seo/lessons/sitemap-xml/).
- Проверьте прямой адрес кабинета и его API без сессии. Сервер должен проверять права до выдачи данных. Кабинет может перенаправить на вход, а API — отказать в доступе. На публичном экране входа можно использовать [`noindex`](/seo/lessons/robots-txt/), если его не нужно показывать в выдаче.
- После публикации проверьте статью в Google Search Console и Яндекс Вебмастере. Смотрите поисковые клики по публичному URL. Если есть веб-аналитика, отдельно отслеживайте завершённые регистрации из таких визитов.

## Практика

Выберите одну функцию приложения и запрос, по которому её могут искать. Решите, чему научит открытая статья и какую работу человек сможет продолжить в кабинете. Проверьте путь в приватном окне: главная → блог → статья → витрина или регистрация. Затем откройте кабинет по прямому адресу и убедитесь, что данные без входа недоступны.
