По запросу «проверить sitemap» в отчёте появились обзор карты сайта и инструкция по ошибкам загрузки. Само пересечение ничего не говорит о проблеме. Сначала проверьте, какую задачу решает каждая страница и по каким формулировкам она получает показы.

## Сравните страницы на одних данных

В одной поисковой панели выберите запрос и период. Сравните URL по показам и кликам, затем посмотрите, какой адрес появлялся чаще в разные недели. Используйте одинаковые фильтры. Вручную откройте выдачу и запишите, ждут ли пользователи определения, проверки готового файла или диагностики ошибки. Выдача может сочетать несколько задач.

| Что обнаружили | Что сделать |
| --- | --- |
| У обзора и инструкции разные задачи | Сохранить обе. Развести заголовки и связать страницы там, где читателю нужен следующий шаг |
| Две статьи повторяют одну инструкцию | Собрать полный ответ на одном URL. При снятии второй версии настроить постоянный редирект |
| По запросу устойчиво показывается неподходящая страница | Проверить целевую страницу, её индексирование, заголовок и ссылки. Уточнить, где на сайте есть нужный ответ |

Для двух разных материалов оставьте самостоятельные канонические URL. Если объединяете статьи, перенесите полезную часть текста, обновите ссылки и sitemap и проверьте перенаправление. Подробнее о настройке есть в [уроке о переносе страниц](/seo/lessons/redirects-and-page-moves/).

## Практика

Выберите запрос с показами двух страниц. Для каждой запишите задачу читателя, показы и клики за тот же период. Выберите один вариант из таблицы и объясните его. Если вносите правку, сохраните исходные данные и после обработки [сравните те же запросы за сопоставимый период](/seo/lessons/measure-seo-changes/).
