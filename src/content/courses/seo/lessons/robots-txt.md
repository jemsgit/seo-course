`robots.txt` — общедоступный текстовый файл с правилами обхода сайта. Робот запрашивает его по адресу вроде `https://example.com/robots.txt`. Файл пригодится, если нужно ограничить обход служебных путей, например результатов внутреннего поиска, или сообщить адрес карты сайта. Правила относятся к тому протоколу, хосту и порту, на которых размещён файл. Для другого поддомена нужен свой файл, если там нужны правила.

Если `/robots.txt` возвращает `404`, отсутствие файла само по себе не мешает обходу. Робот может найти статью по ссылке, запросить её и обработать для поиска. Важно проверить код именно у файла. Ответ `404` от самой статьи означает, что по этому адресу сервер сообщает об отсутствии страницы. Сбой сервера на `/robots.txt` тоже отдельный случай: Google обрабатывает ответы `5xx` иначе, чем `404`.

## Что писать в robots.txt

Для публичного сайта, который можно обходить целиком, подойдёт такой файл:

```text
User-agent: *
Allow: /
Sitemap: https://seo.example.com/sitemap.xml
```

- `User-agent: *` начинает группу правил для роботов, у которых нет своей группы. Для конкретного робота можно указать его имя, например `Googlebot`. При добавлении отдельной группы проверьте, какие правила применятся к этому роботу.
- `Allow: /` разрешает обход всех путей в этом примере. Если ограничений нет, разрешение действует и без этой строки. Более конкретное правило может изменить доступ к отдельному пути.
- `Disallow` запрещает обход указанного пути. Например, `Disallow: /internal-search/` закрывает адреса, начинающиеся с этого пути. Пустой `Disallow:` ничего не запрещает, а `Disallow: /` закрывает обход всего сайта для роботов этой группы.
- `Sitemap` сообщает полный адрес [карты сайта](/seo/lessons/sitemap-xml/), включая `https://`. Добавляйте строку, если карта существует. Директива относится ко всему файлу.

Если нужно закрыть результаты внутреннего поиска, но оставить открытой страницу справки в том же разделе, правила могут выглядеть так:

```text
User-agent: *
Disallow: /internal-search/
Allow: /internal-search/help/
Sitemap: https://seo.example.com/sitemap.xml
```

Путь `/internal-search/help/` разрешён благодаря более конкретному правилу. Для `/internal-search/results/?q=seo` срабатывает запрет. URL, уже известный поисковику по ссылкам, всё ещё может появиться в выдаче. Пользователи смогут открыть его, пока сервер отдаёт страницу всем.

## Как сгенерировать файл автоматически

Если правила и адрес карты постоянны, в Astro достаточно положить текстовый файл в `public/robots.txt`. При сборке он скопируется в корень `dist/`. Если один проект собирается для разных доменов, удобнее подставлять адрес карты из настройки сборки.

На курсе это делает маршрут `src/pages/robots.txt.ts`. Astro выполняет его при статической сборке и записывает результат в `dist/robots.txt`. Вот код курса:

```ts
import type { APIRoute } from 'astro';

export const GET: APIRoute = ({ site }) => new Response(
  'User-agent: *\nAllow: /\n' + (site ? `Sitemap: ${new URL('/sitemap.xml', site)}\n` : ''),
  { headers: { 'Content-Type': 'text/plain; charset=utf-8' } },
);
```

Конфигурация Astro получает `site` из `SITE_URL`. Соберите проект с тестовым доменом и откройте результат:

```sh
SITE_URL=https://seo.example.com npm run build
cat dist/robots.txt
```

Вы увидите первый пример из урока. В сборке без `SITE_URL` строка `Sitemap` пропускается, а страницы курса получают `noindex` в HTML. Готовый файл можно раздавать с обычного статического хостинга. Для одного адреса `/robots.txt` выберите один способ: файл в `public/` или маршрут.

## Когда подходит noindex

Иногда страницу надо оставить доступной по прямому адресу, но исключить из поиска. Например, открытое демо предназначено для читателей конкретного урока. Оставьте доступ для робота и добавьте в `<head>`:

```html
<meta name="robots" content="noindex">
```

То же указание можно передать HTTP-заголовком `X-Robots-Tag: noindex`, например для PDF. Если одновременно закрыть URL через `Disallow`, робот может не получить страницу и не увидеть указание. Для уже известной страницы изменение статуса требует повторной обработки.

## Что выбрать для своей страницы

| Страница | Задача | Настройка |
| --- | --- | --- |
| Опубликованный урок | Дать поисковику возможность обнаружить и прочитать текст | Обычная внутренняя ссылка, ответ `200`, доступ для обхода и индексирования |
| Общедоступное служебное демо | Открывать его по прямой ссылке и исключить из поиска | Доступ для обхода и `noindex` |
| Закрытый предпросмотр | Пускать только участников проекта | Авторизация или ограничение доступа на уровне хостинга |

Для предпросмотра проверяйте доступ без авторизации. На курсе черновики дополнительно исключены из публичной сборки.

Для продукта с кабинетом посмотрите [пример публичного блога и защищённых страниц на одном домене](/seo/lessons/seo-behind-login/).

## Практика

1. Соберите курс с тестовым `SITE_URL`. Сравните `dist/robots.txt` с первым примером и убедитесь, что адрес карты совпадает с доменом сборки.
2. Проверьте ответы для `/robots.txt` и урока на опубликованном сайте. Подставьте свой домен в команду `curl -sS -D - https://seo.example.com/robots.txt`. Если файл есть, найдите группу правил для нужного робота и проверьте путь урока.
3. Возьмите тестовую страницу, которую можно читать по ссылке. Проверьте исходный HTML и HTTP-заголовки на `noindex`. Если URL должен быть исключён из поиска, убедитесь, что робот может получить этот ответ.
4. Откройте закрытый предпросмотр без входа. Убедитесь, что видите экран входа или отказ в доступе. Открытая страница с `noindex` доступна любому посетителю, у которого есть адрес.
