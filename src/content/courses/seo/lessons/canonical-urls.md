Письмо со ссылкой на урок ведёт на `/seo/lessons/sitemap-xml/?utm_source=newsletter`, а программа курса ссылается на `/seo/lessons/sitemap-xml/`. Адреса разные, текст один. Для поиска удобнее выбрать адрес без метки. Ссылка из письма при этом продолжит работать.

## Что такое канонический URL

Канонический URL — основной адрес, который поисковик выбирает для группы одинаковых или очень похожих страниц. Этот адрес обычно представляет всю группу в выдаче. Например, Google может учесть ссылки на оба варианта урока вместе и показать результат с одним адресом. Тег `rel="canonical"` сообщает, какой вариант предпочитает владелец сайта.

## Что будет, если не указать canonical

Страница может попасть в индекс и без тега. Если поисковик обнаружит дубли, он может выбрать основной адрес сам. В нашем примере в выдаче может оказаться URL с UTM-меткой. Ссылки внутри сайта и адреса в sitemap тоже помогают обозначить предпочтительный вариант. Если у страницы один стабильный адрес, отсутствие тега само по себе не мешает её индексированию.

## Сравните, что получают читатели

Параметр в URL иногда меняет саму страницу. Сравните заголовок, основной текст и то, с чем работает человек после перехода. Если параметр меняет набор товаров в каталоге, сначала решите, нужна ли получившаяся подборка как самостоятельная страница поиска.

| Пример                                 | Что проверить                                                       | Настройка                                                                |
| -------------------------------------- | ------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| Урок с `utm_source`                    | Оба адреса возвращают один и тот же урок                            | Сохранить рабочую ссылку с меткой и указать основной адрес без параметра |
| Старый и новый адрес одного урока      | Старый адрес больше не нужен как отдельная страница                 | Вернуть постоянный редирект на новый адрес                               |
| Урок про sitemap и урок про robots.txt | Страницы отвечают на разные вопросы, хотя обе упоминают карту сайта | Дать каждой свой канонический адрес                                      |

## Укажите основной адрес

Добавьте в `<head>` обоих вариантов урока один и тот же абсолютный URL. На основном адресе тег будет указывать на саму страницу.

```html
<link rel="canonical" href="https://seo.example.com/seo/lessons/sitemap-xml/" />
```

Используйте этот адрес во внутренних ссылках и в [карте сайта](/seo/lessons/sitemap-xml/). Проверьте, что он открывается с `200`, доступен для обхода и подходит для индексирования. Если дубль остаётся доступным, робот должен иметь возможность прочитать его HTML и увидеть тег. Если адрес окончательно заменён, используйте [постоянный редирект](/seo/lessons/redirects-and-page-moves/).

## Как настроить Clean-param в Яндексе

Допустим, ваш сайт добавляет параметр `ref` к ссылкам на уроки, чтобы отмечать источник перехода. Сравните `/seo/lessons/sitemap-xml/?ref=newsletter` и `/seo/lessons/sitemap-xml/`. Если обе версии отдают один и тот же урок, можно попросить Яндекс игнорировать `ref` при обработке адресов. Для этого добавьте в [`robots.txt`](/seo/lessons/robots-txt/) строку:

```text
Clean-param: ref /seo/lessons/
```

Слева укажите имя параметра без `?` и значения. После пробела укажите префикс пути. Правило выше действует только на адреса, начинающиеся с `/seo/lessons/`. Если нужно игнорировать несколько параметров, перечислите их через `&`, например `Clean-param: ref&source /seo/lessons/`. Без префикса правило охватит весь сайт. Указывайте его только после проверки, что параметр нигде не меняет содержимое. Например, `page=2` в каталоге открывает другой список товаров, и такой параметр сохраняют.

`Clean-param` можно добавить отдельной строкой в существующий файл. Браузер продолжит открывать ссылку с параметром. Для Google сохраните `rel="canonical"` и ссылки на основной адрес. Некоторые метки, в том числе стандартные UTM, Яндекс может исключать автоматически. Если это уже происходит, добавлять правило для них не требуется.

После публикации откройте сырой `/robots.txt` и проверьте синтаксис в инструменте «Анализ robots.txt» Яндекс Вебмастера. После обработки проверьте вариант URL с параметром в отчёте «Страницы в поиске». Для такого дубля может появиться статус «Исключена по Clean-param». Сверьте и чистый адрес, чтобы убедиться, что исключён именно вариант с параметром.

## Как выбрать формат URL со слешем или без

Для адресов страниц подходят оба варианта. Например, `/seo/lessons/sitemap-xml/` и `/seo/lessons/sitemap-xml` могут вести на один материал, но поисковик может встретить их как два разных URL. Выберите формат, который уже последовательно использует сайт. У курса страницы идут со слешем на конце: в Astro задано `trailingSlash: 'always'`. Для файлов вроде `/sitemap.xml` используйте их точный адрес.

Проверьте, что внутренние ссылки, `canonical` и sitemap указывают на выбранный вариант. Если второй адрес тоже открывает ту же страницу, настройте постоянный редирект на основной там, где раздаётся сайт. У статического курса это настройка хостинга. Поведение проверяйте после публикации:

```sh
curl -sS -D - -o /dev/null https://seo.example.com/seo/lessons/sitemap-xml
curl -sS -D - -o /dev/null https://seo.example.com/seo/lessons/sitemap-xml/
```

Подставьте свой домен. Для формата курса ожидаем `301` или `308` с `Location` на адрес со слешем и `200` на самом адресе со слешем.

## Проверьте выбор поисковика

`canonical` сообщает предпочтение. Поисковик может выбрать другой URL. В Google Search Console откройте проверку URL и, если данные доступны, сравните адрес, указанный владельцем, с адресом, выбранным Google. В Яндекс Вебмастере проверьте, не отмечен ли дубль как неканоническая страница в отчёте об исключённых URL.

Если поисковик выбрал другой адрес, начните со сверки ссылок, sitemap и тегов на обеих страницах. Например, шаблон может указывать на адрес со слешем, а сервер перенаправляет его на адрес без слеша. Исправьте расхождение и проверьте статус после повторного обхода.

## Практика

1. Возьмите два доступных URL одной статьи, например обычный адрес и адрес с UTM-меткой. Убедитесь, что тело урока совпадает.
2. Проверьте `rel="canonical"` в HTML обоих вариантов. Сравните указанный адрес со ссылкой на странице модуля и записью в sitemap.
3. Если сайт опубликован, проверьте оба URL в панелях. Запишите отдельно, какой адрес указывает ваш HTML и что сообщает каждая система.
